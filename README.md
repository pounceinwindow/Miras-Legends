# Мирас — легенды рядом

Мобильная игра о татарских легендах: игрок находит AR-метку, знакомится с хранителем и сразу переходит к испытанию. Викторины и «правильных ответов» в актуальном сценарии нет.

## Запуск

Нужен Node.js 24.

```bash
npm ci
npm run dev
```

Без переменных окружения приложение работает локально, а прогресс хранится в `localStorage`.

## Мобильные приложения

Проект подготовлен для Android и iOS через Capacitor 8. Нативные проекты находятся в `android/` и `ios/`.

```bash
npm run mobile:sync
npm run mobile:android
npm run mobile:ios
```

Для Android нужны Android Studio и JDK 21. Для iOS нужны актуальные Xcode и Apple Developer account. Камера и геолокация уже объявлены в нативных разрешениях.

План публичного запуска, тексты магазинов, сценарии роликов, закрытый тест и партнёрская модель находятся в [`docs/launch/`](docs/launch/README.md). Готовая графика лежит в `marketing/store/`.

## Supabase

Для общего прогресса на телефонах используется Supabase Auth и таблица `game_progress` с RLS. Каждый анонимный пользователь может читать и менять только свою запись.

1. Создайте Supabase-проект.
2. Включите Anonymous Sign-ins в разделе Authentication.
3. Выполните миграцию `supabase/migrations/20260919000000_game_progress.sql` через SQL Editor или Supabase CLI.
   Для аналитики первого маршрута также выполните `supabase/migrations/20260922000000_analytics_events.sql`.
4. Скопируйте `.env.example` в `.env.local` и укажите:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
```

5. Перезапустите Vite или повторно разверните frontend.

`VITE_SUPABASE_ANON_KEY` является публичным клиентским ключом. `service_role` и строку подключения PostgreSQL нельзя добавлять в `VITE_*`.

## Основной сценарий

1. Пользователь открывает сканер на `/home`.
2. MindAR распознаёт приватное исходное изображение по файлу `public/ar/assets/target.mind`. Сам документ с персональными данными в проект не добавляется.
3. Метка `stone-01` открывает Кремль без викторины. Координаты метки загружаются из Supabase `ar_targets`.
4. Для игрока создаётся локальный или Supabase-профиль.
5. Запускается бой Су анасы против Кремля на `/fight/su-anasy?enemy=kereml`.

Сканер не закрывается до успешной подготовки данных и боя. На телефоне камера требует публичный HTTPS-домен; `localhost` считается безопасным только на том же устройстве.

## Маршруты

| Экран | URL |
| --- | --- |
| Главная и сканер | `/home` |
| Карта | `/map` |
| История хранителя | `/encounter/:token` |
| Коллекция | `/collection` |
| Хранитель | `/entity/:id` |
| Бой | `/fight/:character?enemy=:enemy` |
| PvP с другом | `/pvp` |
| Профиль | `/profile` |

## Проверки

```bash
npm run lint
npm test
npm run build
```

Физическое распознавание камеры проверяется отдельно на реальном телефоне. Автоматический тест не заменяет проверку разрешений, HTTPS и конкретной камеры устройства.

## Структура

```text
src/                         React-интерфейс и состояние игры
shared/                      локальная игровая логика
fighting/                    бой «Три русла» и спрайты
public/ar/                   MindAR-сканер и тестовая метка
supabase/migrations/         схема облачного прогресса и RLS
tests/unit/                  тесты игрового контракта
```

Каталог `backend/` сохранён как серверный эксперимент из `main`, но текущий frontend MVP не требует его для подключения к Supabase.
